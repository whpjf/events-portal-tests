# Задание 2. Анализ HTTP-запроса и ответа в DevTools

Открывала вкладку «Сеть» в Chrome (DevTools, окно отдельное от страницы). Разобрала два запроса: вход на своём портале и открытие страницы на настоящем сайте.

## Запрос 1. Вход на портале (POST)

Снимки `01` - `05` в папке `screens`. Запрос отправлен из консоли страницы `http://localhost:8103/login` через `fetch` с `redirect: 'manual'`, потому что при обычной отправке формы браузер сразу переходит дальше и запрос пропадает из списка.

| Что | Значение |
|---|---|
| URL | `http://localhost:8103/login` |
| Метод | `POST` |
| Код ответа | `303 See Other` |
| Заголовок `Location` | `/` (переход на главную) |
| Заголовок запроса `Content-Type` | `application/x-www-form-urlencoded` |
| Тело запроса | `login=anna_k`, `password`, `csrf_token`, `next=/` (вкладка «Полезная нагрузка») |
| Тело ответа | пустое (`Content-Length: 0`) |
| `Set-Cookie` | `konf_session=...; path=/; Max-Age=7200; httponly; samesite=lax` |
| Остальные заголовки ответа | `Referrer-Policy: same-origin`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Vary: Cookie`, `Server: uvicorn` |

Что полезно для тестирования:

- Код 303 после входа нужно проверять в тесте: успех это переход, а не 200.
- Cookie сессии с `httponly` (скрипты страницы её не читают) и `samesite=lax`. Срок 7200 секунд, как в настройках.
- В теле запроса есть `csrf_token`: без него сервер отвечает 403. Это проверено в `tests/test_forms.py` (F-32).
- Пароль уходит открытым текстом, поэтому на настоящем сайте нужен только https (флаг `Secure` включается переменной `PORTAL_HTTPS=1`).

Вкладка «Ответ» у `GET /login` (`05-portal-get-otvet.png`) показывает HTML формы, в нём скрытое поле `csrf_token` со значением, которое хранится в сессии.

## Запрос 2. Открытие страницы на настоящем сайте (GET)

Снимки `06` - `08`. Страница: `https://ru.wikipedia.org/wiki/Тестирование_программного_обеспечения`, строка с типом «Документ» в списке запросов. Всего при загрузке страницы около 35 запросов (скрипты, стили, шрифты, картинки).

| Что | Значение |
|---|---|
| Метод | `GET` |
| Код ответа | `200 OK` |
| Заголовок ответа `Content-Type` | `text/html; charset=UTF-8` |
| `Content-Language` | `ru` |
| `Content-Encoding` | `gzip`, передано 48 673 байт |
| `Cache-Control` | `private, s-maxage=0, max-age=0, must-revalidate, no-transform` (страницу не кешируют) |
| `Strict-Transport-Security` | `max-age=106384710; includeSubDomains; preload` |
| `Content-Security-Policy` | длинный список разрешённых источников скриптов |
| Тело запроса | нет (у GET его не бывает), тело ответа это HTML страницы (вкладка «Ответ») |

Что полезно для тестирования: у страницы кеширование отключено, а у скриптов и стилей (`load.php`, первый снимок списка) срок хранения около 30 дней (`max-age=2592000`). Поэтому после изменений на сайте тестировщику нужно сбрасывать кеш или включать «Отключить кеш» в DevTools.

Сравнение двух запросов: у GET нет вкладки «Полезная нагрузка», а у POST есть; POST отвечает перенаправлением и ставит cookie, GET возвращает документ и ничего не ставит.
