## Баг-репорты

Найдено шесть ошибок. Все описаны одинаково: версия `996a8f7`, Windows 11, Chrome 157, адрес `http://localhost:8103`. Исправления в репозитории портала, коммиты `3678bcd` и `0ec50c6`. Скриншоты в папке `screens`.

**BR-01. Страница мероприятия с очень большим номером отвечает 500**
Серьёзность: средняя. Приоритет: средний.
Шаги: открыть `http://localhost:8103/events/99999999999999999999`.
Ожидалось: страница «Страница не найдена».
Получилось: белая страница «Internal Server Error». В журнале сервера `OverflowError: Python int too large to convert to SQLite INTEGER`.
Вложение: `screens/BR-01-ogromnyj-id-500.png`. Статус: исправлен (номер в адресе ограничен 2147483647).

**BR-02. Ошибочные адреса отвечают текстом JSON**
Серьёзность: низкая. Приоритет: средний.
Шаги: открыть `/nope`, затем `/events/abc`, затем `/logout` обычным переходом (там ответ 405).
Ожидалось: страница сайта с шапкой и ссылкой на главную.
Получилось: голый текст `{"detail":"Not Found"}`, для `/events/abc` длинный JSON с `int_parsing`.
Вложения: `screens/BR-02-nesushchestvuyushchij-adres-json.png`, `screens/BR-02b-bukvy-v-adrese-json.png`. Статус: исправлен.

**BR-03. Поиск не находит слово, написанное маленькими буквами**
Серьёзность: средняя. Приоритет: высокий (поиск основной способ найти мероприятие).
Шаги: на афише ввести `закваска`, нажать «Найти». Потом ввести `Закваска`.
Ожидалось: оба раза находится «Закваска и хлеб дома».
Получилось: на `закваска` «Ничего не найдено», на `Закваска` одно мероприятие. Причина: SQLite не различает регистр только у латинских букв.
Вложения: `screens/BR-03-poisk-malenkimi-bukvami.png`, `screens/BR-03b-poisk-s-zaglavnoj.png`. Статус: исправлен.

**BR-04. Один логин можно занять дважды в разном регистре**
Серьёзность: высокая. Приоритет: высокий.
Шаги: зарегистрироваться с логином `ANNA_K` (учётная запись `anna_k` уже есть).
Ожидалось: сообщение «Такой логин уже занят».
Получилось: регистрация прошла, в шапке `ANNA_K`. В базе два пользователя, выглядящие одинаково.
Вложение: `screens/BR-04-login-v-drugom-registre.png`. Статус: исправлен (поиск по `lower(login)` и уникальный индекс).

**BR-05. Заявку можно отправить на прошедшее мероприятие**
Серьёзность: средняя. Приоритет: средний.
Шаги: войти как `oleg_s`, открыть `/events/1/apply` (мероприятие прошло, на странице мероприятия кнопки нет), заполнить форму, отправить.
Ожидалось: отказ с пояснением.
Получилось: «Заявка отправлена», в «Мои заявки» появилась заявка на «Пчеловодство: первый сезон» от 19.09.2026.
Вложения: `screens/BR-05-proshedshee-bez-knopki.png`, `screens/BR-05b-zayavka-na-proshedshee.png`. Статус: исправлен.

**BR-06. Длинное слово в названии ломает афишу на телефоне**
Серьёзность: низкая. Приоритет: средний.
Шаги: администратором добавить мероприятие с названием из 100 букв «Ж» без пробелов, открыть афишу на ширине 390.
Ожидалось: название переносится внутри карточки.
Получилось: название вылезает за карточку, страница шире экрана на 2089 px (в автотесте на окне 500 px на 1994 px), появляется горизонтальная прокрутка.
Вложение: `screens/BR-06-dlinnoe-nazvanie-390.png`. Статус: исправлен (`overflow-wrap: anywhere`).

Кроме шести описанных, при проверке форм нашлись ошибки с переводом строки в конце логина и почты, паролем из пробелов, телефоном из арабских цифр и почтой `a@b.c`, а также завершение заявки администратором до даты мероприятия. Они разобраны в задании 3 и тоже исправлены. Не исправлено: старая cookie после выхода продолжает работать до конца срока (2 часа).
